## Key integration recommendations

1. **Adopt a propose->evaluate->gate loop over static prompts, GEPA/SkillOpt/ACE as design sources** - Optimize agents/\*.md, skills/ and tools/ descriptions as text parameters (image/AGENTS.md is not an optimizer target in the local implementation). Use GEPA (MIT, Pareto reflective evolution) as an out-of-band dev-host optimizer or reimplement its accept/reject core in stdlib Python; borrow SkillOpt's validation-gated update and best-artifact output; borrow ACE's Generator/Reflector/Curator delta updates for a curated playbook section. RECOMMENDATION (not what is implemented): outputs should be a reviewable diff/PR with no in-cluster self-edit. IMPLEMENTED locally instead: opt-in --promote that atomically rewrites one Markdown target after the gate passes.
   - Local status: Partially realized conceptually by scripts/12-self-improve.py (gate+holdout+promote); no upstream package; no Pareto/DSPy.

2. **Make the gate stricter than the published tools** - Third-party audit (page read) reports no-op optimizers, mean-only gates accepting regressions, held-out leakage and missing admission ledgers (gepa-ai/gepa#381 open; microsoft/SkillOpt#67 closed). Require: per-task non-regression, held-out split the optimizer never sees, immutable evaluator/gate files outside the optimizer's write scope, negative-control probes, and an append-only admission ledger (JSONL) recording accept/reject reasons.
   - Local status: Holdout split + paired no-regression gate implemented. Immutable-evaluator enforcement, negative-control probes and a verified append-only admission ledger: not verified in this review (run reports exist under docs/explanation/self-improvement-runs/).

3. **Use deterministic signals first; LLM judge second** - Primary gates: agents/ci-check.sh, tests/, rtk/Headroom token metrics from scripts/11-token-benchmark.py. Secondary: Agent-as-a-Judge with a different, frozen judge model. Reflexion/Self-Refine style bounded retries with test feedback.
   - Local status: Deterministic exact-decision gate implemented; LLM judge, Reflexion retries with test feedback not implemented.

4. **Route lessons into Engram with provenance, promote to AGENTS.md only via gate** - ExpeL/Reflexion/Dynamic Cheatsheet patterns: trajectory-mined lessons stored in Engram with source run, date, evidence; promotion to image/AGENTS.md requires the loop gate. Treat Engram as an attack surface (DrunkAgent memory-corruption threat model).
   - Local status: Not implemented (no Engram promotion path verified).

5. **Benchmarks: small local suite first, external subsets later** - Extend scripts/11-token-benchmark.py / tests with a frozen local task suite; optionally sample SWE-bench / SWT-Bench / TDD-Bench / BFCL subsets (benchmark-only) once Substrate gVisor can host their harnesses.

6. **Keep self-modifying-code systems research-only** - DGM, HGM, Hyperagents, Godel Agent, ShinkaEvolve, Live-SWE-agent, Ouroboros etc. execute self-written code, are compute-heavy, and some have unclear licenses (Hyperagents NOASSERTION). Not planned; sandbox (gVisor, no credentials, tenant-gateway injection) is the precondition if ever revisited.

7. **Skip weight-training, multimodal, web/GUI, embodied, games** - No training infra in AX/kind stack; domains are outside coding-agent scope.
